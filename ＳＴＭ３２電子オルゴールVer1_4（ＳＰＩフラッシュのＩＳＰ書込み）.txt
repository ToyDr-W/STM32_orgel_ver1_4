【前振り】

おもちゃ修理のマイコン換装で、ＳＰＩフラッシュはＳＯＰパッケージを使って基板に直付けしている。実装事例は <a href="https://tutujith.blog.fc2.com/blog-entry-985.html" target="_blank" title="ここ"><span style="color:#FF0000"><strong>ここ</strong></span></a>。その理由は

・ＤＩＰパッケージ品に比べてＳＯＰパッケージ品はかなり廉価である。

・ソケットを使うとコストが掛かるのと、おもちゃの内部は余裕が無く、ソケットを使うと収まらなくなることがある。

このようなメリットがあるが、組み付け（はんだ付け）後に書き替えるのが難しい。それで、組み付け後にも実装状態で書き替える、所謂ＩＳＰの仕掛けを作った。


【設計】

①ＩＳＰを行うための構成。

<a href="https://tutujith.blog.fc2.com/img/202609252036046be.jpg/" target="_blank"><img src="https://blog-imgs-160.fc2.com/t/u/t/tutujith/202609252036046be.jpg" alt="ＳＴＭ３２電子オルゴールVer1_4（ＳＰＩフラッシュのＩＳＰ書込み）構成" border="0" width="818" height="282" /></a>

・ターゲットのマイコンにＳＰＩフラッシュの書き替えを行わせる。そのためのアプリケーションをターゲットのマイコンにダウンロードして実行する。

・ターゲットで実行するアプリケーションは元のプロジェクトでのピン割り当て（回路構成）を使用する。そうしなければＩＳＰが成り立たない。従って、元の電子オルゴールのアプリケーションをベースにして開発し、ｍａｉｎ．ｃとｃｎｆ．ｂａｔの設定内容はＳＰＩフラッシュへアクセスを行う設定になっている必要がある。

・書き込みデータはＰＣからシリアルで伝送する。そのためのＰＣ側のアプリケーションを作る。

・ターゲット側のシリアルポートは、従来のデバグ情報ポートを転用する。内蔵ＵＳＡＲＴが１個のみ実装されたマイコンではデバグ情報出力のシリアル通信は別のピンに疎開して、ソフト実装する。

・ＩＳＰのためにターゲット側に必要なリソースはシリアル通信ポートとＳＰＩポートである。これらのリソースは既存のものであり、ＩＳＰのために必要な新たなリソースは無い。

②ＰＣ側のツール

・チップ消去と書き込みの機能を提供する。

・それぞれの機能毎にバッチコマンドを用意する。

・チップ消去コマンドは　ERASE.bat　で、内容は下記。

@echo off
:: ==========================================
:: ★ ここに 使用したいCOMポート番号ボーレート を指定してください
set COM_PORT=COM12
set BAUD_RATE=230400
:: ==========================================

:: 通信設定
mode %COM_PORT%:%BAUD_RATE%,n,8,1

:: 1. 送信処理
<nul set /p ="ERASE" > \\.\%COM_PORT%

:: 2. 受信処理と表示（PowerShell側にもバッチの変数 %COM_PORT% を渡しています）
powershell -Command "$port = New-Object System.IO.Ports.SerialPort('%COM_PORT%', %BAUD_RATE%, 'None', 8, 'One'); $port.ReadTimeout = 30000; $port.Open(); try { $response = $port.ReadLine(); Write-Output $response } catch [TimeoutException] {  } finally { $port.Close() }"

pause

・書き込みコマンドは　WRITE.bat　で、内容は下記。

@echo off
:: ==========================================
:: ★ ここに 使用したいCOMポート番号とボーレート、HEXファイル名を指定してください
set COM_PORT=COM12
set BAUD_RATE=230400
set HEX_FILE=W25Q.hex
:: ==========================================

:: 通信設定
mode %COM_PORT%:%BAUD_RATE%,n,8,1

:: 1. 送信処理
<nul set /p ="WRITE" > \\.\%COM_PORT%

:: 2. 受信処理と表示（PowerShell側にもバッチの変数 %COM_PORT% を渡しています）
powershell -Command "$port = New-Object System.IO.Ports.SerialPort('%COM_PORT%', %BAUD_RATE%, 'None', 8, 'One'); $port.ReadTimeout = 1000; $port.Open(); try { $response = $port.ReadLine(); Write-Output $response } catch [TimeoutException] {  } finally { $port.Close() }"

echo "WRITE START"

..\hexsend\Release\hexsend.exe %COM_PORT% %BAUD_RATE% %HEX_FILE%

echo "WRITE END"

pause

・ターゲットへの書き込みデータの転送機能は、MicrosoftVisualC++でC言語のコンソールアプリケーションを作る。

転送機能のコンソールアプリケーションは　hexsend　で、内容はダウンロードファイルを参照

・ＣＯＭポートとボーレート、及びＨＥＸファイル名はバッチコマンド内のｓｅｔコマンドで設定する。開発プロジェクト内ではパラメータは固定されるのでＧＵＩは用意しない。

・転送内容は、アドレス情報（２バイト）＋書き込みデータ（２５６バイト）＋チェックサム（１バイト）＝全体で２５９バイトを１ブロックとして転送する。

アドレス情報はＳＰＩフラッシュへ送る２４ビットアドレスの上位１６ビット分
書き込みデータは２５６バイト境界
チェックサムはアドレス情報と書き込みデータの各バイトのＸＯＲを計算した結果

・１ブロックを転送の都度、ターゲットから処理結果を受信する。ターゲットから異常が返された場合は処理を中断する。

・ＨＥＸファイルの若番アドレスから老番アドレスへブロックを順次転送する。２５６バイト境界で存在しない部分は０ｘｆｆで埋める。書き込みデータの２５６バイトがすべて０ｘｆｆであるブロックは転送しない。

・プログレスバーの代わりに、１２８ｋバイトを転送する毎に、「＊」を１個表示していく。１６Ｍビットを転送する場合は１６個が表示されて終了する。

③マイコン側のツール

・ＰＣからシリアル通信で動作指示と書き込みデータを受信して、チップ消去と書き込みを実行する。

・ＰＣからの書き込みデータが２５６バイトブロックで順次転送され、ブロック毎に書き込みと照合を行う。

・プロトコル外れ、伝送エラー、照合不一致など、異常が発生した場合はその旨のエラーをＰＣへ応答する。

・ツールの内容（コード）はダウンロードファイルを参照。


【実行】

①ＰＣ側の環境

・ツールと実行用バッチコマンドの雛形はダウンロードファイルの　orgel1_4\tool_ISP_SPIFLASH　にある。

・ツールのプロジェクト（MicrosoftVisualC++2008）は　hexsend。

・ＰＣ環境により、バッチコマンド内のｓｅｔコマンドを変更して実行する。

②ターゲット側の環境

・プロジェクトは　orgel_SW_F030C6 ISP。元のプロジェクトは　orgel_SW_F030C6。

・構成（ピン割り当て）は下記の赤印の既存のピン割り当てを利用する。

・ターゲットにプロジェクトのＨＥＸファイルをダウンロードし、実行する。

・その後に、ＰＣ側のバッチコマンドを実行する。

③実行手順

・ターゲットに　orgel_SW_F030C6 ISP　をダウンロードして、起動しておく。

・ＰＣ側でバッチコマンド　ERASE.bat　を実行する。実行完了までに最大２０秒掛かる。正常終了すると「ＯＫ」が表示される。

【おまけ】
